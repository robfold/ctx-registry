An open-source alternative to Context7

Up-to-date docs for your agents. On your own edge. No quota.

ctx-registry does what Context7 does. Your coding agent connects one MCP address, asks a question, and gets back the right sections of a library's official docs. The difference is where it runs: a Cloudflare Worker on your own account, with no monthly cap, at about $11 per million questions.

Where a shared docs service gets in the way

From the public issue tracker of Context7, the hosted docs service most coding agents use today.

ctx-registry answers from your own Cloudflare account. No one else's quota sits between your agent and the docs, and a library's docs change when you publish them.

How it works

Your agent speaks MCP to one Worker. The Worker searches two ways at once and returns the best sections.

  1. Deploy the Worker

    One Worker, a D1 database for keyword search, and a Vectorize index for meaning search.

    npm run cf:deploy

  2. Load official docs

    Build a package from a library's repo or docs site, then index it on your Worker.

    context add https://github.com/honojs/hono
node bin/ctx-index.mjs --all

  3. Connect your agent

    Any MCP client that connects over HTTP. For Claude Code:

    claude mcp add --transport http docs https://ctx-registry.<you>.workers.dev/t/<READ_TOKEN>/mcp

  4. Ask

    The agent finds the library, then asks its question, the same way it uses Context7.

    resolve-library-id  libraryName: "next"
query-docs          libraryId: "next@16.4.6"
                    query: "protect a dashboard route"

What changes for your agents

The same two tools as Context7
  • Prompts that say "resolve the library, then query the docs" keep working.
  • A Context7-style ID such as /vercel/next.js resolves too.
Keyword and meaning search together
  • Ask about "middleware" and it still finds Next.js 16's "proxy" docs.
  • An exact API name still matches word for word.
You pick the source and the version
  • Build from the maintainers' own repo or docs site.
  • next@16.2.9 and next@16.4.6 stay side by side, so agents read the version you run.
No quota
  • There is no monthly cap to run into in the middle of a task.
  • You pay Cloudflare for what you use: about $11 per million questions at list price.

Clone it, then run eight commands

You need a Cloudflare account on Workers Paid and Node 22.13 or later.

Deploy the Worker

git clone https://github.com/robfold/ctx-registry
cd ctx-registry
npm install
npx wrangler d1 create ctx-docs
npx wrangler d1 migrations apply ctx-docs --remote
npx wrangler vectorize create ctx-docs-vectors --dimensions=1024 --metric=cosine
npx wrangler r2 bucket create ctx-registry
npm run cf:deploy
openssl rand -hex 32 | npx wrangler secret put READ_TOKEN
openssl rand -hex 32 | npx wrangler secret put PUBLISH_TOKEN

Paste the database id that d1 create prints into wrangler.jsonc before the migration. Until both tokens are set, every path except /healthz answers 404.

Connect an agent

{
  "mcpServers": {
    "docs": {
      "url": "https://ctx-registry.<you>.workers.dev/t/<READ_TOKEN>/mcp"
    }
  }
}

Clients that can send headers can use /mcp with Authorization: Bearer <READ_TOKEN> instead, so the token stays out of the URL.

What it doesn't do yet

  • Answers are the docs' own sections. Context7 also writes a short summary for each code example; ctx-registry does not.
  • You choose and load the libraries. There is no shared catalog of thousands of libraries, and automatic rebuilds are not in this release.
  • The read token works like an API key. There is no rate limit for anyone who holds it.
  • From some networks, workers.dev traffic takes a long route; put the Worker on your own domain if that matters.
