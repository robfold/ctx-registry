Official docs for your agents. Your version. No quota.

ctx-registry is a self-hosted registry for the open-source context CLI. Build a package from a library's official docs once, and every machine and agent installs that exact version from your own Cloudflare account. Libraries you haven't built come from the public registry, so nothing else changes.

Where hosted docs get in the way

From the public issue tracker of Context7, the hosted docs service most coding agents use today.

ctx-registry builds each package from the official source you pick, keeps every version you pin, and serves it from your own Cloudflare account. Once installed, a package is searched on the agent's machine: no quota to hit, no outage to wait out.

How it works

Your agents keep using the context CLI and its MCP server. Only the server it downloads from changes.

  1. Build a package

    Turn a repo, a docs site, or a folder into one SQLite file on your machine.

    context add https://github.com/honojs/hono

  2. Publish it

    Upload one file, or everything you have built. Packages the server already holds are skipped.

    node bin/ctx-publish.mjs --all

  3. Install it anywhere

    Any machine, any agent, from the CLI or through the MCP tools.

    context install npm/next 16.4.6

  4. Search it offline

    The search runs on the agent's machine. No network call, no meter.

    context query next@16.4.6 "middleware"

What changes for your agents

Search runs where the agent runs
  • No per-query bill, however often an agent looks something up.
  • Installed docs keep working offline, and when the server is down.
Built from the official source you pick
  • You choose the repo or docs site, so agents read the maintainers' own docs.
  • A package changes when you rebuild and publish it, not when someone else's index refreshes.
One server for everything
  • Packages you don't hold stream through from the public registry.
  • Switching is one entry in ~/.context/config.json, and so is switching back.
Versions sit side by side
  • next@16.2.9 and next@16.4.6 both stay installable.
  • Agents read the docs for the version you actually run.

Clone it, then run five commands

You need a Cloudflare account and Node 22.13 or later.

Deploy the Worker

git clone https://github.com/robfold/ctx-registry
cd ctx-registry
npm install
npx wrangler r2 bucket create ctx-registry
npm run cf:deploy
openssl rand -hex 32 | npx wrangler secret put READ_TOKEN
openssl rand -hex 32 | npx wrangler secret put PUBLISH_TOKEN

Until both tokens are set, every path except /healthz answers 404. Keep both tokens in your password manager.

Point the CLI at it

{
  "servers": [
    { "name": "mine", "default": true,
      "url": "https://ctx-registry.<you>.workers.dev/t/<READ_TOKEN>" },
    { "name": "neuledge", "url": "https://api.context.neuledge.com" }
  ]
}

Save it as ~/.context/config.json on each machine. To go back, delete the mine entry: the CLI returns to the public registry.

What it doesn't do yet

  • The read token sits in a URL. Treat it like an API key, and rotate it with one command if it leaks.
  • There is no rate limit for anyone who holds the read token.
  • Each package must be under 95 MB.
  • Packages are built on your machine. Automatic rebuilds are not in this release.
