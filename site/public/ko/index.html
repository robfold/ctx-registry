공유 문서 서비스가 발목을 잡는 곳

지금 코딩 에이전트가 가장 많이 쓰는 문서 서비스 Context7의 공개 이슈 게시판에서 옮겼습니다. 원문은 영어입니다.

ctx-registry는 내 Cloudflare 계정에서 답합니다. 에이전트와 문서 사이에 남의 한도가 없고, 라이브러리 문서는 내가 올릴 때 바뀝니다.

동작 방식

에이전트는 Worker 하나와 MCP로 이야기합니다. Worker는 두 가지 방식으로 동시에 찾아 가장 맞는 절을 돌려줍니다.

  1. Worker 배포

    Worker 하나, 단어 검색용 D1 데이터베이스, 의미 검색용 Vectorize 색인을 띄웁니다.

    npm run cf:deploy

  2. 공식 문서 올리기

    라이브러리 저장소나 문서 사이트로 패키지를 만들고, Worker에 색인합니다.

    context add https://github.com/honojs/hono
node bin/ctx-index.mjs --all

  3. 에이전트 연결

    HTTP로 연결하는 MCP 클라이언트면 됩니다. Claude Code는 이렇게 합니다.

    claude mcp add --transport http docs https://ctx-registry.<you>.workers.dev/t/<READ_TOKEN>/mcp

  4. 질문

    에이전트는 Context7을 쓸 때처럼 라이브러리를 찾고, 질문합니다.

    resolve-library-id  libraryName: "next"
query-docs          libraryId: "next@16.4.6"
                    query: "protect a dashboard route"

에이전트에게 달라지는 것

Context7과 같은 도구 두 개
  • 「라이브러리를 찾고, 문서에 질문하라」는 프롬프트가 그대로 통합니다.
  • /vercel/next.js 같은 Context7식 ID도 찾아 줍니다.
단어 검색과 의미 검색을 함께
  • "middleware"를 물어도 Next.js 16의 "proxy" 문서를 찾습니다.
  • 정확한 API 이름은 글자 그대로 맞춥니다.
출처와 버전을 내가 정합니다
  • 메인테이너가 직접 쓴 저장소나 문서 사이트로 만듭니다.
  • next@16.2.9와 next@16.4.6을 나란히 둡니다. 에이전트는 내가 쓰는 버전을 읽습니다.
한도가 없습니다
  • 작업 중간에 월 한도에 걸려 멈추지 않습니다.
  • 쓴 만큼 Cloudflare에 냅니다. 정가로 질문 100만 개에 약 11달러입니다.

Context7 수치는 2026년 11월 21일에 context7.com/plans에서 읽었습니다. Context7은 공개 라이브러리 수천 개를 대신 올려 둡니다. ctx-registry는 내가 쓰는 라이브러리를 직접 올립니다.

ctx-registry 추정(Cloudflare 정가 기준): 질문 1개는 1,024차원 Vectorize 조회 1번(100만 차원당 $0.01), 질문 임베딩 1번, Worker 요청 1번입니다. 우리가 올린 117,819개 절을 한 번 임베딩하는 비용은 1달러 미만으로 추정합니다.

우리 에이전트가 직접 씁니다

  • 196개 라이브러리 공식 문서
  • 117,819개 절, 단어와 의미로 검색
  • 0.25–0.38초답 하나의 서버 시간(예열 상태 실측)

"로그인한 사용자만 대시보드 경로를 보게 하려면?"을 물으면 Next.js 인증 가이드의 Authorization 절을 먼저, 그다음 Proxy로 하는 낙관적 확인을 돌려줍니다. 처리 코드에는 시험 40개가 있고, 방어 코드를 하나씩 일부러 깨서 시험이 실패하는지 확인했습니다.

클론한 뒤 명령 여덟 줄로 배포

Workers Paid 플랜의 Cloudflare 계정과 Node 22.13 이상이 필요합니다.

Worker 배포

git clone https://github.com/robfold/ctx-registry
cd ctx-registry
npm install
npx wrangler d1 create ctx-docs
npx wrangler d1 migrations apply ctx-docs --remote
npx wrangler vectorize create ctx-docs-vectors --dimensions=1024 --metric=cosine
npx wrangler r2 bucket create ctx-registry
npm run cf:deploy
openssl rand -hex 32 | npx wrangler secret put READ_TOKEN
openssl rand -hex 32 | npx wrangler secret put PUBLISH_TOKEN

d1 create가 보여 주는 데이터베이스 ID를 마이그레이션 전에 wrangler.jsonc에 붙여 넣습니다. 두 토큰을 넣기 전에는 /healthz 말고 모든 경로가 404입니다.

에이전트 연결

{
  "mcpServers": {
    "docs": {
      "url": "https://ctx-registry.<you>.workers.dev/t/<READ_TOKEN>/mcp"
    }
  }
}

헤더를 보낼 수 있는 클라이언트는 /mcp와 Authorization: Bearer <READ_TOKEN>을 씁니다. 그러면 토큰이 URL에 남지 않습니다.

아직 못 하는 것

  • 답은 문서 원래의 절입니다. Context7은 코드 예시마다 짧은 요약을 따로 써 두지만, ctx-registry는 쓰지 않습니다.
  • 라이브러리는 내가 골라 올립니다. 수천 개를 담은 공용 목록이 없고, 자동 재빌드는 이번 판에 없습니다.
  • 읽기 토큰은 API 키처럼 동작합니다. 토큰을 가진 쪽에는 사용량 제한이 없습니다.
  • 일부 통신망에서는 workers.dev 주소가 먼 길로 돕니다. 중요하면 Worker를 내 도메인에 붙입니다.

에이전트에게 내 소유의 문서 서버를 주세요.
